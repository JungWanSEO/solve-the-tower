# Solve the Tower

수학 선생 친구를 위한 슬더슬 같은 수학게임

수학을 포기했던 주인공이 문제를 풀어 몬스터와 싸우며 수학의 탑을 오르는 스마트폰용 로그라이크 웹 게임입니다. 갈림길 지도에서 길을 골라 보스까지 올라가고, 쓰러지면 처음부터 다시 시작합니다.

이 문서는 사용설명서처럼 위에서부터 순서대로 따라 하면 되도록 썼습니다.

## 2. 실행해 보기

파일을 더블클릭해서 열면 동작하지 않습니다. 브라우저가 보안상 데이터 파일을 읽지 못하게 막기 때문입니다. 아래 둘 중 하나로 실행합니다.

**내 컴퓨터에서**

1. 이 폴더에서 터미널을 엽니다.
2. `python -m http.server 8000` 을 실행합니다. (VS Code의 Live Server 확장도 됩니다.)
3. 브라우저에서 `http://localhost:8000` 을 엽니다.

**스마트폰에서 (GitHub Pages)**

1. 저장소의 Settings → Pages 로 갑니다.
2. Source 를 "Deploy from a branch" 로 두고 브랜치와 `/ (root)` 를 고른 뒤 Save 를 누릅니다.
3. 잠시 뒤 `https://<계정>.github.io/solve-the-tower/` 로 접속합니다.

개발 중에는 `dev` 브랜치를, 정식 배포 뒤에는 `main` 브랜치를 보게 합니다.

**처음부터 다시 해 보고 싶을 때**

진행 기록은 서버가 아니라 이 기기의 브라우저에만 저장됩니다. **설정 → 데이터 관리**에서 다음을 할 수 있습니다.

| 기능 | 하는 일 |
| --- | --- |
| 저장된 용량 보기 | 진행 기록과 오프라인용 파일이 각각 얼마나 차지하는지 |
| 기록 내보내기 | 기록을 글자 코드(`STT1-…`)로 만들어 복사하거나 파일로 저장 |
| 기록 가져오기 | 코드를 붙여 넣거나 파일에서 읽어 복원. 다른 기기나 홈 화면 앱으로 옮길 때 사용 |
| 기록 초기화 | 진행 기록과 도감만 지움. 언어와 소리 설정은 남음 |
| 모두 지우기 | 기록, 오프라인용 파일, 서비스 워커 등록까지 이 기기에서 전부 지움 |

지우기 전에는 무엇이 사라지는지 보여 주는 확인 창이 뜨고, "먼저 기록 내보내기"를 고를 수 있습니다.

**아이폰에서 기록이 사라질 수 있습니다.** 사파리는 사파리를 쓴 날로 7일 동안 들르지 않은 사이트의 저장 데이터를 자동으로 지웁니다. 홈 화면에 추가한 앱은 지워지지 않습니다. 그래서 아이폰 사파리로 열면 처음 화면에 안내가 나오고, 데이터 관리 화면에 홈 화면 추가 방법이 있습니다. 사파리에서 하던 기록을 홈 화면 앱으로 옮길 때는 내보내기 → 가져오기를 씁니다.

백업 코드는 `js/save.js` 의 `encodeSave` / `decodeSave` 가 만들고 읽습니다. 읽을 때는 모양이 맞는 값만 받아들이고 나머지는 기본값으로 둡니다.

튜토리얼은 처음 하는 사람에게 한 번만 나옵니다. 화면을 어둡게 가리고 눌러야 할 곳만 밝게 보여 주며, 화살표 달린 말풍선으로 설명합니다.

- 10단계입니다: 출발 칸 → 적의 체력과 약점 → 다음 턴 예고 → 내 체력과 필살기 → 기본 공격 → 스킬 → 강한 공격 예고 → 방어 → 강화 고르기 → 다음 칸. 필살기와 연속기는 처음 쓸 수 있게 됐을 때 따로 한 번 알려 줍니다.
- 튜토리얼의 세 문제(기본 공격, 스킬, 방어)는 **정답을 알려 줍니다.** 정답이 노랗게 빛나고 다른 답은 누를 수 없습니다. 조작을 배우는 자리라, 틀려서 흐름이 어긋나지 않게 한 것입니다. 그 뒤 "자유롭게 싸우기"부터는 평소처럼 풉니다.
- 전투 도중에 건너뛰면 그 연습 전투를 끝내고 **지도로 돌아가** 체력이 가득 찬 상태로 처음부터 시작합니다.
- 말풍선의 **건너뛰기**로 언제든 끝낼 수 있습니다. 한 번 끝내거나 건너뛰면 새 지도를 시작해도 다시 나오지 않습니다.
- 다시 보고 싶으면 처음 화면의 **튜토리얼 다시 보기**를 누릅니다. (튜토리얼을 끝낸 뒤에만 보입니다)
- 문제를 푸는 동안에는 화면을 가리지 않고 위쪽 노란 줄에 한 문장만 나옵니다.

단계와 문구는 `js/tutorial.js` 의 `GUIDES` 에서 고칩니다. 강조할 곳은 CSS 선택자로 적고, 위치는 `js/guide.js` 가 화면에서 직접 재므로 화면 크기가 달라도 어긋나지 않습니다.

## 3. 게임 방법

### 처음 화면

- **이어서 하기**: 진행 중인 지도가 있으면 나옵니다. 하던 곳에서 계속합니다.
- **시작하기 / 처음부터 다시**: 범위를 고르고 새 지도에서 출발합니다. 진행 중인 지도가 있으면 확인 창이 뜨고, **지우고 새로 시작** 을 눌러야 지워집니다.
- **도감 / 튜토리얼 / 설정**: 큰 버튼 아래의 작은 버튼 줄입니다. 도감은 유형별 기록(단원별 정복 막대)과 만난 몬스터(얼굴 그림 포함), 튜토리얼은 다시 보기(한 번 끝낸 뒤에만 보임)입니다.
- 맨 위에는 탑 그림과 제목이, 그 아래에는 지금까지의 기록(이긴 전투, 탑 클리어)이 한 줄로 나옵니다.
- **설정**: 처음 화면의 작은 버튼 줄과 게임 중 메뉴에서 엽니다. 바꾸면 바로 적용되고 이 기기에 저장됩니다.

  | 묶음 | 항목 | 하는 일 |
  | --- | --- | --- |
  | 소리 | 음악, 효과음 | 막대로 음량을 따로 조절. 맨 왼쪽이면 꺼짐 |
  | 화면 | 언어 | 日本語 / 한국어 / English |
  | 화면 | 큰 글씨 | 문제와 답의 글자를 16px → 19px 로 (약 1.2배). 답 버튼 높이도 52 → 58px. 이때는 그림을 덜 줄이는 대신, 작은 폰에서는 조금 스크롤할 수 있음 |
  | 화면 | 연출 줄이기 | 흔들림, 반짝임, 화면 전환 효과를 끔 (기기의 "동작 줄이기"와 같은 효과) |
  | 게임 | 격려 받기 | 끄면 연달아 쓰러져도 도움이 붙지 않음 |
  | 게임 | 데이터 관리 | 백업, 홈 화면 안내, 지우기 화면으로 이동 |

  설정은 `js/settings.js` 가 맡고, 값은 저장 기록의 `opt` 에 들어갑니다. 소리는 파일 없이 `js/sound.js` 가 직접 만듭니다. `SOUNDS` 표를 고치면 효과음이, `TRACKS` 표(빠르기, 화음 진행, 짚는 순서)를 고치면 음악이 바뀝니다. 음악은 세 곡입니다: 지도·상점 등(`calm`), 전투(`battle`), 중간 보스·보스(`boss`).
- **메뉴**: 게임 중 어느 화면에서나 위쪽 **메뉴** 버튼(또는 스마트폰의 뒤로 버튼, 키보드 Esc)으로 잠시 멈춥니다. **계속하기** 와 **처음 화면으로 나가기** 가 있습니다. 전투 도중에 나가면 그 전투는 처음부터 다시 하고, 체력과 힌트는 그대로 저장됩니다.

### 범위 고르기

새 지도를 시작할 때마다 이번 판에 나올 문제 유형을 고릅니다.

- 단원은 접혀 있습니다. 단원 줄을 누르면 유형 목록이 펼쳐지고, 옆의 **모두 고르기 / 모두 빼기** 로 단원을 통째로 넣거나 뺄 수 있습니다. 줄 왼쪽의 색은 전부 고름(초록), 일부만 고름(노랑), 안 고름(회색)입니다.
- 유형마다 정답률과 정복 여부가 보입니다. 부족한 유형만 골라 집중할 수 있습니다.
- **전체**, **미정복만**, **지난번과 같게** 버튼으로 빠르게 고를 수 있습니다.
- 유형을 하나 더 넣을 때마다 전투 골드가 5%씩 늘어납니다. (최대 50%)
- 고른 범위에 어려운 단계의 문제가 없으면 가장 가까운 단계의 문제가 대신 나옵니다.
- 적의 약점 유형도 고른 범위 안에서 정해집니다.
- 아래쪽에 이 범위에서 쓸 수 있는 **연속기 묶음 수**가 나옵니다. 연속기는 한 묶음의 유형을 모두 골라야 나옵니다.

### 지도

1. 지도는 탑의 안쪽을 그린 것으로, 10층입니다. 맨 아래 **입구**에서 출발할 칸을 고르고, 맨 위의 보스까지 올라갑니다.
2. 길로 이어진 칸으로만 갈 수 있습니다. 어느 길로 갈지는 직접 정합니다.
3. 5층에는 중간 보스가 있고, 그 바로 아래 층(4층)에는 휴식 칸이 적어도 하나 있습니다. 중간 보스 방에 들어갈 때는 방 앞의 샘에서 체력을 8 회복합니다(한 번만). 보스 바로 아래 층은 항상 휴식입니다. 1~2층의 보통 전투는 적의 체력이 낮습니다(몸풀기).
4. 지도는 시작할 때마다 새로 만들어집니다.

2. 행동을 고릅니다.
   - **기본 공격**: 쉬운 문제가 나옵니다. 맞히면 약한 피해를 줍니다.
   - **스킬**: 어려운 문제가 나옵니다. 맞히면 큰 피해를 줍니다.
   - **연속기**: 한 상황에서 물음 (1), (2), (3)을 이어 풉니다. 맞힐 때마다 피해 2 → 3 → 6을 주고, 틀리면 거기서 끝나 적의 공격을 받습니다. 한 전투에 한 번만 쓸 수 있습니다. 이번 범위에 풀 수 있는 묶음이 없으면 버튼이 보이지 않습니다.
   - **방어**: 쉬운 문제가 나옵니다. 맞히면 피해를 받지 않고 반격합니다. 틀리면 피해를 절반 받습니다. 연속으로는 쓸 수 없습니다.
3. 문제가 나오면 답을 고릅니다. 시간 제한은 없습니다.
4. 맞히면 적의 보통 공격을 받지 않습니다. 틀리면 공격이 빗나가고 적의 공격을 받으며, 해설이 나옵니다. 틀린 문제는 답 바로 아래에 **정답과 풀이 카드**가 뜨고, **확인했어요, 다음** 을 눌러야 넘어갑니다.
5. 3문제를 연속으로 맞히면 필살기를 쓸 수 있습니다. 틀리면 게이지가 0이 됩니다.
6. 적의 약점 유형 문제를 맞히면 피해가 1.5배입니다.
7. **강한 공격**(3턴마다, 붉은 예고)은 문제를 맞혀도 맞습니다. 방어로만 막을 수 있습니다.
8. 힌트를 쓰면 틀린 보기 하나가 지워집니다.
9. 틀린 직후에 메뉴로 나가도 받기로 된 피해는 받습니다. 보물 상자, 휴식, 석상은 한 번 문제를 보거나 쓰면 나갔다 와도 다시 할 수 없습니다.
10. 체력이 0이 되면 게임 오버입니다. 골드와 강화는 사라지고, 새 지도로 처음부터 다시 시작합니다. 도감 기록은 남습니다.

적은 3턴마다 강한 공격을 합니다. 강한 공격은 공격 문제를 맞혀도 피할 수 없고 방어로만 막을 수 있습니다. 예고를 보고 그 턴에 방어하는 것이 요령입니다.

### 다시 도전할 때: 선물, 격려, 도전 단계

한 판이 끝나면(쓰러지든 깨든) 다음 판은 조금 다르게 시작합니다. 못 깬 사람은 점점 쉬워지고, 깬 사람은 더 어려운 규칙을 고를 수 있습니다.

**숫자 칸 채우기 (도전 6단계의 보스전)**

일본 공통테스트의 마크시트처럼, 답의 모양은 보여 주고 숫자 자리만 비워 둡니다. 예: 답이 `3√2/2` 이면 `□√□/□` 가 나오고, 숫자판(0~9, −, 지우기)으로 칸을 채운 뒤 **이 답으로 공격**을 누릅니다.

- 칸은 정답 글의 숫자와 − 부호마다 하나씩 생깁니다. 그래서 `1/2` 와 `0.5` 중 무엇으로 쓸지 고민할 일이 없습니다.

- 판정과 화면은 `js/battle.js` 의 `makeFill`, `renderFill`, `typeFill` 입니다.

문제는 대부분 공식 하나로 풀리는 한 단계 문제입니다. 여러 물음을 이어 푸는 문제는 **연속기**로 나옵니다. 지금 묶음은 10개입니다: 대칭식(x² + y² → (x − y)² → x³ + y³), 호제법(나머지 → 최대공약수 → 기약분수의 분모), 이차함수(완전제곱식 → 꼭짓점 → 최댓값), 이차식(판별식 → 방정식의 해 → 부등식의 해), 삼각형(변 → 넓이 → 내접원의 반지름), 직각삼각형(빗변 → sin A → 내접원의 반지름), 확률(경우의 수 → 확률 → 기댓값), 뽑기(뽑아서 세우기 → 뽑기만 → 한 명이 반드시 포함), 원에 내접하는 사각형(마주 보는 각 → 중심각 → 접선과 현의 각), 정수(최대공약수 → 최소공배수 → 곱). 직각삼각형과 원 묶음에는 그림이 붙고, 물음마다 구할 곳이 노란 이름표로 표시됩니다.

**보스 전용 묶음(킬러 묶음)과 검수 중인 묶음**

| 묶음에 적는 값 | 뜻 |
| --- | --- |
| `"boss": true` | 보스전에서만 나오는 어려운 묶음. 보스전의 연속기 버튼은 이 묶음을 먼저 냅니다 |
| `"draft": true` | 아직 검수 중. 평소에는 나오지 않고, 주소 끝에 `?draft=1` 을 붙여 열었을 때만 (어느 전투에서든, 다른 묶음보다 먼저) 나옵니다 |

지금은 예시가 하나 있습니다: 数学I 二次関数의 `chain-killer` (문자 a가 든 이차함수: 꼭짓점 → 최솟값 m의 최댓값 → 최솟값이 정해진 값이 되는 a). 선생님 검수를 받는 중이라 `draft` 가 켜져 있습니다. 검수가 끝나면 `"draft": true` 한 줄을 지우면 보스전에 나옵니다.

문제는 `data/units/<단원>.json` 에 있습니다. **문장 틀**과 **숫자 묶음**으로 나뉘어 있어서, 숫자만 다른 문제는 한 줄만 추가하면 3개 언어로 모두 나옵니다.

**숫자만 다른 문제 추가**

해당 틀의 `items` 에 한 줄을 더합니다.

```json
{ "d": 20, "deg": 45, "answer": "20 m", "wrong": ["10√2 m", "22 m", "10 m"] }
```

- `answer`: 정답
- `wrong`: 오답 보기 3개. 정답과 겹치면 안 됩니다.
- 나머지(`d`, `deg` 등): 문장 틀의 `{d}`, `{deg}` 자리에 들어갈 값

**새로운 종류의 문제 추가**

`templates` 에 틀을 하나 더합니다.

| 항목 | 뜻 |
| --- | --- |
| `id` | 틀의 이름 (영문, 겹치지 않게) |
| `level` | 1 = 개념 확인, 2 = 계산, 3 = 응용 |
| `type` | 유형. 파일 위쪽 `types` 에 있는 이름이어야 합니다 |
| `text` | 문제 문장. ja, ko, en 세 가지를 모두 씁니다 |
| `explain` | 틀렸을 때 보여줄 해설 한 줄 |
| `items` | 숫자 묶음 목록 |

**숫자를 자동으로 만드는 문제**

틀에 `items` 대신 `"gen": "<이름>"` 을 적으면 `js/generators.js` 의 생성기가 매번 새 숫자를 만듭니다. 오답 보기는 "사인 대신 코사인을 쓴 값"처럼 흔한 실수에서 나오는 값으로 만들어집니다.

새 생성기를 추가할 때는 답이 깔끔하게 떨어지는 숫자만 쓰도록 하고, 정답과 값이 같은 오답이 생기지 않게 `item()` 과 `choose()` 를 그대로 씁니다.

**문제에 그림 붙이기**

틀에 `figure` 를 적으면 그 틀의 모든 문제에 그림이 붙습니다. 숫자는 `items` 에서 자동으로 들어갑니다.

```json
"figure": { "kind": "triangle", "angle": "θ", "opp": "{a}", "adj": "{b}", "hyp": "{c}" }
```

| kind | 그림 | 적을 수 있는 자리 |
| --- | --- | --- |
| `triangle` | 직각삼각형 | `angle` 각, `opp` 맞은편 변, `adj` 이웃 변, `hyp` 빗변 |
| `tower` | 탑 하나 | `angle` 올려본 각, `dist` 수평거리, `height` 높이 |
| `twopoint` | 탑과 두 지점 | `far` 먼 지점의 각, `near` 가까운 지점의 각, `gap` 두 지점 사이, `height` 높이 |
| `anytri` | 삼각형 ABC | `angleA` `angleB` `angleC` 각, `sideA` `sideB` `sideC` 변 (a는 A와 마주 보는 변) |

구해야 하는 자리에는 `"?"` 를 적습니다. 표시하지 않을 자리에는 `""` 를 적습니다.

**어느 단계가 어디에 나오나**

| 단계 | 나오는 곳 |
| --- | --- |
| 1 | 기본 공격, 방어, 휴식의 복습 |
| 2 | 스킬, 보물, ? 칸의 석상, 보스의 기본 공격 |
| 3 | 보스의 스킬 |

**문제의 조건 적기** (`note`)

답을 내는 데 필요한 약속은 문제 문장에 섞지 않고 `note` 에 따로 적습니다. 화면에서는 문제 아래에 노란 점선 상자로 "조건: …" 이 나옵니다.

```json
"note": { "ja": "x は実数とする。", "ko": "x는 실수이다.", "en": "x is a real number." }
```

이런 것을 적습니다: 수의 범위(x 는 실수, x ≠ 0), 근삿값(원주율은 3.14 로 계산한다), 무시할 것(눈높이는 생각하지 않는다), 계산 방식(분산은 n 으로 나눈다), 같은 것으로 보는 기준(돌려서 같으면 같은 배열). 문제의 숫자를 넣을 수도 있습니다. (`"x ≠ {a}"`)

**보기가 말인 문제** (`@이름`)

보기가 숫자나 식이 아니라 말이면, 생성기에서 보기를 `"@suf"` 처럼 적고 세 언어 파일의 `opt` 에 문구를 둡니다. 필요조건·충분조건 문제가 이렇게 되어 있습니다. 보기가 길면 답 버튼이 자동으로 한 줄에 하나씩 놓입니다.

**그림 붙이기** (`figure`)

도형 문제에는 그림이 꼭 있어야 합니다. 틀에 `figure` 를 적으면 문제의 숫자가 그림에 들어갑니다. 구하는 값은 `"BD = ?"` 처럼 `?` 를 넣어 적으면 노란 이름표가 됩니다.

| kind | 그림 | 적는 값 |
| --- | --- | --- |
| `triangle` | 직각삼각형 | angle, opp, adj, hyp |
| `tower`, `twopoint` | 탑과 관측 지점 | angle, dist, height / far, near, gap, height |
| `anytri` | 삼각형 ABC | angleA~C, sideA~C |
| `bisect` | 각의 이등분선 | ab, ac, bc, bd |
| `median` | 중선과 무게중심 | am, ag |
| `incenter` | 내심 | angleA, bic |
| `circleangle` | 원주각과 중심각 (외심) | central, insc, names, chord |
| `cyclic` | 원에 내접하는 사각형 | angleA, angleC |
| `chords` | 원 안에서 만나는 두 현 | pa, pb, pc, pd |
| `tangent` | 할선과 접선 | pa, pb, pt |
| `cuboid` | 직육면체 | ab, ad, ae, ag |
| `space` | 두 지점에서 본 탑 (∠AHB = 90°) | angleA, angleB, ab, ph |
| `incircle` | 삼각형과 내접원 | ab, bc, ca, r 또는 af |
| `ceva` | 체바의 정리 | af, fb, bd, dc, ce |
| `tanchord` | 접선과 현 | acb, bat |
| `grid` | 격자 길 | cols, rows |
| `histogram` | 히스토그램 | freq, from, step |
| `boxplot` | 상자그림 | five |
| `scatter` | 산포도 | pts |
| `tetra` | 정사면체 | edge, h |
| `menelaus` | 메넬라우스의 정리 | ar, rb, bp, cq |

도형 그림 아래에는 "그림은 실제 길이·각도와 다르게 그려져 있습니다" 가 자동으로 붙습니다. (통계 그래프와 격자 길은 정확한 그림이라 붙지 않습니다.) 새 그림은 `js/figures.js` 의 `DRAW` 에 추가합니다.

**연속기 묶음 추가하기** (`chains`)

단원 파일에 `templates` 와 나란히 `chains` 를 둡니다. 공통 지문(`intro`)과 물음 목록(`steps`)으로 이루어집니다.

```json
"chains": [{
  "id": "chain-quad", "gen": "quad",
  "intro": { "ja": "関数 {f} について答えよ。", "ko": "함수 {f}에 대하여 답하시오.", "en": "…" },
  "steps": [
    { "type": "complete", "level": 2, "sum": { "ko": "완전제곱식", … }, "text": { … }, "explain": { … } },
    { "type": "vertex", "level": 1, "sum": { "ko": "꼭짓점", … }, "text": { … }, "explain": { "ko": "{a1}에서 꼭짓점은 {answer}", … } }
  ]
}]
```

| 항목 | 뜻 |
| --- | --- |
| `gen` | `js/generators.js` 의 `CHAINS` 에 있는 생성기 이름. 숫자 묶음 하나에서 물음별 정답과 오답을 한꺼번에 만듭니다 |
| `intro` | 모든 물음 위에 계속 보이는 공통 지문 |
| `figure`, `note` | 묶음 전체에 붙는 그림과 조건 (물음마다 `note` 를 따로 줄 수도 있습니다) |
| `steps[].type` | 그 물음의 유형. 도감에는 이 유형으로 기록됩니다. 묶음의 유형이 모두 범위에 있어야 그 묶음이 나옵니다 |
| `steps[].sum` | 풀고 난 뒤 한 줄 요약에 쓰는 이름. 예: "(1) 꼭짓점: (2, −1)" |
| `{a1}`, `{a2}` | 앞 물음의 정답. 뒤 물음의 문장과 해설에 쓸 수 있습니다 |

피해량은 `js/config.js` 의 `damage.chain` 입니다.

**단원 추가하기**

1. `data/units/` 에 단원 파일을 만듭니다. (기존 `math1-trig.json` 을 복사해 고치면 됩니다.)
2. `data/catalog.json` 의 해당 과목 `units` 에 파일 이름을 추가합니다. 과목이 없으면 과목도 추가합니다.
3. 범위 고르기 화면과 도감에 저절로 나타납니다.

단원 파일의 `groups` 는 범위 고르기 화면에서 유형을 묶어 보여주는 소제목입니다.

| --- | --- |
| 90% | 거의 항상 |
| 75% | 4번 중 3번쯤 |
| 60% | 4번 중 1번쯤 |

## 8. 몬스터 추가하는 법

**지금 있는 몬스터** (모두 학생이 자주 하는 실수를 본떴습니다)

| 몬스터 | 단원 | 뜻하는 실수 | 고유 동작 |
| --- | --- | --- | --- |
| 사코 쌍둥이 | 삼각비 | 사인과 코사인을 바꿔 쓰기 | 둘이 자리를 바꿈 |
| 부호 박쥐 | 삼각비 | 플러스와 마이너스를 틀리기 | 날개의 부호를 뒤집음 |
| 덜약분 골렘 | 삼각비 | 약분하지 않은 답 | 약분되면 작아짐 |
| 괄호 슬라임 | 수와 식 | (a + b)² 의 가운데 항 2ab 빠뜨리기 | 2ab 를 삼킴 |
| 부등호 게 | 수와 식 | 음수로 나눌 때 부등호를 안 바꾸기 | 집게의 부등호가 뒤바뀜 |
| 포물선 유령 | 이차함수 | 꼭짓점의 부호를 반대로 읽기 | 축의 반대쪽으로 넘어감 |
| 뒤죽박죽 막대 (꺼 둠) | 데이터의 분석 | 정렬하지 않고 중앙값 구하기 | 크기 순서로 줄을 섬 |
| 중복 주사위 | 경우의 수와 확률 | 같은 경우를 두 번 세기 | 똑같은 주사위가 하나 더 나타남 |
| 보조선 컴퍼스 | 도형의 성질 | 보조선을 긋지 않고 풀기 | 점선으로 보조선을 그음 |
| 단위 도둑 (중간 보스) | 삼각비 | 단위를 빠뜨리거나 틀리기 | 단위 자루를 들어 올림 |
| 이항 마술사 (중간 보스) | 수와 식 | 이항할 때 부호를 안 바꾸기 | 부호가 그대로인 카드를 넘김 |
| 이상값 거인 (중간 보스, 꺼 둠) | 데이터의 분석 | 이상값에 끌려간 평균을 믿기 | 혼자 뛰어올라 평균선을 올림 |
| 안개 탑 (보스) | 삼각비 | 그림을 그리지 않고 풀기 | 안개로 높이를 가림 |
| 판별식 용 (보스) | 이차함수 | 해가 있는지 확인하지 않고 풀기 | 배의 D 부호가 바뀜 |
| 나머지 생쥐 | 정수 | 몫과 나머지를 바꿔 쓰기 | 치즈의 q 와 r 을 바꿔 듦 |
| 법칙 저울 (중간 보스) | 경우의 수와 확률 | 합의 법칙과 곱의 법칙을 바꿔 쓰기 | 저울이 반대로 기욺 |
| 원의 문지기 (보스) | 도형의 성질 | 정리의 조건을 확인하지 않기 | 삼각형이 원 밖으로 커짐 |

보통 전투, 중간 보스, 보스 모두 **이번 판의 범위에 들어 있는 단원의 몬스터**가 먼저 나옵니다. (`"midboss": true`, `"boss": true` 가 여럿이면 그중에서 고릅니다.) 약점 유형이 범위에 없으면 범위 안에서 하나가 대신 정해집니다.

1. `data/monsters.json` 에 항목을 추가합니다. (`id`, 이름, 뜻하는 실수, 체력, 약점 유형)
2. `js/stage.js` 에 그리는 함수를 하나 만들고 `FOE_DRAW` 에 같은 `id` 로 등록합니다.

그림은 이미지 파일 없이 원, 다각형, 선으로 그립니다. 기존 `drawBat` 을 복사해 고치는 것이 가장 빠릅니다. `"boss": true` 를 넣으면 지도의 마지막 칸에 나옵니다.

## 9. 스마트폰 화면 맞춤

스마트폰은 화면 크기가 제각각이고, 브라우저의 주소 줄 때문에 실제로 보이는 높이는 더 작습니다. (아이폰 15 는 844 가 아니라 사파리에서 약 664) 그래서 **고정된 크기로 만들지 않고, 보이는 높이를 재서 맞춥니다.**

## 9-1. 불러오기 속도와 오프라인

전체 용량은 약 360KB(압축하면 100KB 안팎)로 작습니다. 느리게 느껴졌던 이유는 용량이 아니라 **파일을 하나씩 차례로 기다렸기 때문**입니다. 지금은 이렇게 합니다.

| 한 일 | 있는 곳 |
| --- | --- |
| 코드 파일 20여 개를 한꺼번에 받기 | `index.html` 의 `modulepreload` |
| 글·문제·몬스터 데이터를 한꺼번에 받기 | `js/main.js` 의 `boot`, `js/questions.js` 의 `loadAll` |
| 받는 동안 진행 막대, 6초가 넘으면 "통신이 느립니다", 실패하면 이유와 "다시 시도" | `index.html` 의 `#loading` |
| 한 번 열면 기기에 저장 → 다음부터는 통신 없이 바로 열림, 오프라인에서도 실행 | `sw.js` |
| 새 버전이 올라오면 "새 버전이 준비됐습니다 · 새로 고침" 알림 | `sw.js`, `js/main.js` 의 `watchUpdate` |
| 전투 화면이 아닐 때는 캐릭터 그림판을 쉬게 함 | `js/stage.js` 의 `loop` |

**고쳐서 올릴 때 꼭 할 일: `sw.js` 의 `VERSION` 을 바꿉니다.** 바꾸지 않으면 이미 열어 본 사람에게는 예전 화면이 계속 나옵니다. 처음 화면 맨 아래에 지금 버전이 작게 적혀 있어서, 새 버전이 적용됐는지 바로 확인할 수 있습니다. 파일을 새로 만들었으면 `sw.js` 의 `FILES` 와 `index.html` 의 `modulepreload` 에도 추가합니다.

게임 안에서 화면이 넘어갈 때는 통신을 하지 않습니다. 느린 폰을 흉내 낸 측정에서도 가장 긴 전환(처음 화면 → 범위 고르기)이 0.3초 이내였습니다.

## 9-2. 고친 뒤 확인하기 (검사 도구)

`tools/` 폴더에 검사 도구가 있습니다. 게임은 이 폴더 없이 동작합니다.

| 명령 (`tools/` 에서) | 확인하는 것 |
| --- | --- |
| `npm run verify` | 모든 문제의 정답을 다른 방법으로 다시 계산해 대조. 검사가 안 붙은 문제 틀도 찾아냄 |
| `npm run balance` | 정답률이 다른 봇들이 여러 판을 해서 클리어율과 쓰러진 층을 측정. 게임 숫자를 고쳤을 때 사용 |
| `npm run play` | 봇이 게임을 끝까지 여러 판 진행. 오류와 빠진 번역 확인 |
| `npm run layout` | 스마트폰 14가지 크기에서 답 버튼이 화면 밖으로 밀리는지 측정 |
| `npm run perf` | 느린 통신에서 첫 화면이 뜨는 시간 측정 |

준비와 결과 읽는 법은 `tools/README.md` 에 있습니다. **문제를 새로 만들면 검사도 같이 만듭니다.** 안 만들면 `verify` 마지막 줄에 `NOT VERIFIED` 로 나옵니다.

## 9-3. 브랜치 규칙 (git-flow)

| 브랜치 | 쓰임 |
| --- | --- |
| `main` | 배포용. 정식 공개 뒤 GitHub Pages 가 이 브랜치를 보여줍니다. 직접 커밋하지 않습니다. |
| `dev` | 개발용. 완성된 기능이 모이는 곳입니다. |
| `feature/<이름>` | 기능 하나를 만드는 곳. `dev` 에서 만들고 `dev` 로 합칩니다. |
| `release/<버전>` | 배포 준비. `dev` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |
| `hotfix/<이름>` | 배포된 것의 급한 수정. `main` 에서 만들고 `main` 과 `dev` 양쪽에 합칩니다. |

**기능 하나를 만드는 순서**

```
git switch dev
git switch -c feature/offline
(작업하고 커밋)
git switch dev
git merge --no-ff feature/offline
```

**배포하는 순서**

```
git switch -c release/0.1.0 dev
(버전 확인, 마지막 수정, CHANGELOG.md 의 "다음 버전" 을 버전 번호로 바꾸기)
git switch main
git merge --no-ff release/0.1.0
git tag v0.1.0
git switch dev
git merge --no-ff release/0.1.0
```
