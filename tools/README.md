# 검사 도구

게임을 고친 뒤 문제가 없는지 확인하는 도구입니다. 게임 자체는 이 폴더 없이 동작하고, 여기 있는 것은 배포되어도 쓰이지 않습니다.

## 준비 (한 번만)

```
cd tools
npm install
```

Node.js 20 이상이 필요합니다. 화면 검사(`layout`, `perf`)에는 크롬이 필요하고, 크롬 위치가 다르면 `CHROME=/크롬/경로` 를 앞에 붙입니다.

## 쓰는 법

| 명령 | 하는 일 | 언제 |
| --- | --- | --- |
| `npm run verify` | 모든 문제 생성기를 수천 번씩 돌려, 따로 계산한 값과 정답을 대조합니다. 오답 보기가 정답과 같아지는 경우, 보기 중복, 문장에 빈칸이 남는 경우도 찾습니다 | 문제나 생성기를 고쳤을 때 |
| `npm run play` | 화면 없이 봇이 게임을 끝까지 여러 판 합니다. 오류, 번역이 빠진 글, 언어 전환을 확인합니다 | 게임 규칙이나 화면을 고쳤을 때 |
| `npm run balance` | 정답률이 다른 봇들이 여러 판을 해서 클리어율과 쓰러진 층을 표로 보여 줍니다 | 체력·피해·보상 같은 숫자를 고쳤을 때 |
| `npm run layout` | 스마트폰 14가지 크기에서 문제 화면을 띄워, 답 버튼이 화면 밖으로 밀리는지, 옆으로 넘치는지, 누르는 곳이 너무 작은지 잽니다 | 화면 배치를 고쳤을 때 |
| `npm run perf` | 느린 통신에서 첫 화면이 뜨기까지 걸리는 시간과 요청 수를 잽니다 | 파일을 추가하거나 불러오는 방식을 고쳤을 때 |

`layout` 과 `perf` 는 게임이 `http://localhost:8765/` 에서 열려 있어야 합니다. 저장소 폴더에서 `python3 -m http.server 8765` 를 먼저 실행합니다.

## 결과 읽는 법

- `verify`: 파일마다 줄 끝의 `problems 0` 이 정상입니다. 문제가 있으면 `PROBLEM` 줄에 틀 이름, 만들어진 숫자, 이유가 나옵니다. 마지막의 `verify-coverage` 는 어느 파일에서도 검사하지 않은 틀이 있으면 `NOT VERIFIED` 로 알려 줍니다. 새 문제를 만들고 검사를 안 붙였을 때 여기서 걸립니다.
- `play`: `"errors":[]` 와 `untranslated keys on screen: []` 가 정상입니다. 숫자 두 개는 정답률과 판 수입니다. (`node play.mjs 0.6 5`)
- `layout`: 기기마다 한 줄씩 나옵니다. `answers below fold: 0px` 가 정상입니다. 2016년 아이폰 SE 1세대(320×454)만 일부 문제에서 0 이 아닙니다.

## 새 문제를 만들었을 때

생성기를 추가하면 `verify-*.mjs` 중 하나의 `OK` 표에 **생성기와 다른 방법으로** 답을 확인하는 줄을 추가합니다. 같은 공식을 그대로 옮겨 적으면 생성기가 틀렸을 때 검사도 같이 틀립니다. 가능하면 직접 세거나(경우의 수), 대입해 보거나(방정식), 정의대로 계산합니다(분산).
- `balance`: `node balance.mjs 120 0.5,0.6,0.7` 처럼 판 수와 정답률을 줄 수 있습니다. 숫자를 저장소에서 고치지 않고 시험해 보려면 `TUNE='{"config":{"player":{"hp":36}}}' node balance.mjs`, 도전 단계는 `SAVE='{"ascend":3,"ascendMax":5}' node balance.mjs` 로 잽니다. 봇은 행동을 무작위로 고르므로 사람보다 조금 못합니다. 절대값보다 고치기 전후의 차이를 보세요.
- `node export-art.mjs`: 지금 게임의 주인공과 몬스터를 투명 배경 PNG 로 뽑아 `art/reference/` 에 저장합니다. 그림을 새로 그릴 사람에게 주는 참고 그림입니다. (게임을 `python3 -m http.server 8765` 로 띄운 상태에서 실행)
